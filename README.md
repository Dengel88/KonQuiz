# KonQuiz — бэкенд

Пошаговая стратегия-викторина для Telegram Mini App (в духе Triviador): 3 игрока,
карта из 15 территорий, случайные замки → экспансия (угадайка, 2+1 земли) → 4 раунда боёв. Правила — классика Конкизтадора/Triviador, см. «Правила» ниже.
Стек: FastAPI + WebSocket, SQLAlchemy 2.0 async, PostgreSQL, Redis.

## Быстрый старт локально (без Docker, Postgres и Redis)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
copy .env.example .env   # раскомментировать блок «Локально»
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8765
```

Открыть http://127.0.0.1:8765/ — сам Mini App. Вне Telegram вход идёт через dev-режим; чтобы
открыть второго игрока в соседней вкладке, добавьте `?dev=2`. Через 15 секунд пустые места займут
боты. Технический стенд — http://127.0.0.1:8765/demo/. Тесты:
`.\.venv\Scripts\python.exe -m pytest`.

Быстрые боты для ручной проверки (переменные окружения перед запуском uvicorn):
`REVEAL_TIME=2 BOT_DELAY_MIN=0.8 BOT_DELAY_MAX=1.6 MATCHMAKING_TIMEOUT=2`.

## Фронтенд (app/static/game)

Чистый JS-модуль без сборщика: Node на сервере не нужен. `js/net.js` отвечает за авторизацию,
REST и WebSocket с переподключением, `js/map.js` — за SVG-карту, `js/app.js` — за экраны и
логику. Клиент ничего не решает сам: он рисует последний снимок `state` и отправляет намерения.

Стиль «тьма + янтарь» (DESIGN_REFERENCE.md). Карта — «золотой слиток» (свечение, тень, фаска —
статичные SVG-слои), «камера» (`MapView.fit`) наезжает на допустимые для хода земли и на
участников боя, тап по мелкому региону притягивается к ближайшему допустимому (`snap`).
Счёт в HUD — живой (земли + столица), считается на клиенте только для показа.

## Карты

Каждая карта — JSON в `app/game/maps/` (id = имя файла), у матча поле `map_id`, у каждой пары
(тема, карта) своё лобби. Карта по умолчанию — `russia` (`DEFAULT_MAP` в `map_topology.py`).
**Соседство вычисляется из геометрии**, поэтому на экране видны ровно те границы, через которые
сервер разрешает атаки. После перегенерации нужно перезапустить сервер.

- `python tools/gen_map_russia.py` → `russia.json`: 15 регионов из субъектов РФ (Natural Earth
  admin-1 1:50m, public domain; скачивается в `tools/.cache/`, нужен `shapely` из
  requirements-dev). Состав регионов — таблица `GROUPS`. Проекция Альберса + «лупа» над
  европейской частью (`FISH_*`), иначе на телефоне мелкие регионы не попасть пальцем.
- `python tools/gen_map.py [seed]` → `island.json`: Вороной на «дрожащей» сетке 3×5, остров.

## Вопросы

Банк лежит в `app/seed_data.py`, по категориям и со сложностью 1–3. `python -m app.seed`
добавляет только новые вопросы (сравнение по тексту), поэтому правки в базе не затираются.
Поле `verified` означает «проверено человеком», при заливке оно `false`. `tests/test_seed_data.py`
ловит дубли, повторы среди вариантов ответа и числа, которые нельзя набрать на клавиатуре.

## Как устроено

```
app/
  main.py            FastAPI-приложение, сборка зависимостей (lifespan)
  api.py             REST + WebSocket /ws + тестовые эндпоинты
  auth.py            проверка Telegram initData (HMAC) + dev-обход
  models.py          User, Question, QuestionRating, Match, MatchParticipant
  game/
    engine.py        MatchEngine — актор матча: очередь событий, таймеры, подсказки, финал
    states.py        состояния FSM (паттерн State)
    bots.py          боты — отдельные asyncio-задачи
    manager.py       реестр матчей и лобби
    schemas.py       MatchState/PlayerState (Pydantic) + публичное представление
    services.py      вопросы, экономика, Redis-хранилище, шина событий
    map_topology.py  карты (maps/*.json), resolve(map_id)
  static/index.html  демо-клиент
```

**Один матч — один актор.** Действия игроков, ответы ботов, таймауты и подключения
попадают в одну очередь `MatchEngine.inbox` и обрабатываются строго по одному. Гонок
нет по построению, блокировки не нужны. Таймер несёт токен: после «заморозки» или
смены состояния старый таймаут игнорируется. Каждое действие может нести `phase` —
ответ, отправленный в прошлую фазу, отклоняется.

**Боты** подписаны на шину матча и отвечают через `engine.submit()` — тем же путём и
тем же payload, что клиент по WebSocket.

**Redis** хранит снимок `MatchState` после каждого события (TTL 1 час). Источник
истины при этом — память процесса. Поэтому пока **один воркер uvicorn**
(`--workers 1`). Восстановление матчей после рестарта не реализовано: активные матчи
при перезапуске теряются.

### Состояния

`MATCHMAKING` → `REALM_REVEAL` ×3 (замки раздаются случайно, по ролику на каждый) → `EXPANSION` → `EXPANSION_PICK` ×(2+1)
→ `BATTLE_WAIT` → `BATTLE_QUESTION` (→ `BATTLE_TIEBREAKER`; при штурме замка — снова `BATTLE_QUESTION`, пока атакующий не ошибётся) → …
→ (`FINAL_TIEBREAKER`, если очков поровну) → `END_GAME`.
Между вопросом и следующим шагом — `REVEAL` (3 с, `REVEAL_TIME`): пауза, чтобы
клиент показал правильный ответ и анимацию.

### Решения сверх ТЗ

| Ситуация | Правило |
|---|---|
| Кто-то не выбрал территорию/атаку за отведённое время | сервер выбирает случайно |
| Одинаково близкие числовые ответы | побеждает тот, кто ответил раньше (время фиксирует сервер) |
| Экспансия | только соседняя с вашими землями нейтральная (если такой нет — любая) |
| Бой: оба правы | тайбрейкер (вопрос с числом), а не «кто быстрее» |
| Бой: никто не ответил в тайбрейкере | защитник удерживает |
| Замок | 1000 очков, 3 башни; каждый выигранный бой роняет башню, осада идёт, пока атакующий не ошибётся; последняя башня — атакующий забирает все очки и земли, владелец выбывает |
| Игрок без земель | выбывает, ходы пропускаются; остался один — матч заканчивается |
| Очки | живые: земля в экспансии +200; захват +400 атакующему, защитник теряет стоимость земли, земля теперь стоит 400; руины замка ±1000; удачная оборона (верный ответ на первый вопрос) +100 |
| Цели по раундам | 1 — соседние без замков; 2–3 — соседние и замки; 4 (последний) — любая земля, лидер по очкам бьёт первым |
| Равенство в конце | финальная угадайка между лидерами |
| Подсказки | сначала из запаса (`hints_*`), если пусто — золото; 50/50 и радар только для вопросов с вариантами; боты не используют |
| Отключившийся игрок | его ответа не ждём; при переподключении получает полный снимок |
| Бот и год | ошибка ±15 лет вместо ±30% (флаг `Question.is_year`) |

## Протокол WebSocket

Подключение: `wss://host/ws?init_data=<Telegram.WebApp.initData>[&match_id=...][&topic=...][&map=...]`.
Без `match_id` игрок попадает в лобби (или возвращается в свой активный матч).

От клиента (поле `phase` — из последнего состояния, рекомендуется всегда):
```json
{"action": "answer", "value": 2, "phase": 17}          // CHOICE: индекс варианта; EXACT: число
{"action": "pick", "territory": 8, "phase": 18}
{"action": "attack", "source_territory": 4, "target_territory": 3, "phase": 40}
{"use_hint": "50_50" | "freeze" | "radar", "phase": 17}
```
От сервера: `welcome` (полный снимок), `state` (снимок после каждого события),
`hint` / `error` (только вам), `end` (итоги; затем сокет закрывается).
В снимке нет правильного ответа и чужих ответов — только кто уже ответил.
Итог вопроса приходит в `last_result`.

## Эндпоинты

- `GET /api/health`, `GET /api/maps`, `GET /api/map?map_id=`, `GET /api/matches/{id}`
- `POST /api/questions/{id}/rate` `{"value": 1|0|-1}` — оценка вопроса после ответа (одна на игрока, перезаписывается)
- `GET /api/me` — заголовок `X-Init-Data`
- Только при `ENABLE_TEST_ENDPOINTS=true`:
  `POST /api/test/match` — матч «1 человек + 2 бота»;
  `POST /api/test/simulate?autopilot=true|false` — прогон целого матча на ускоренных таймерах.

## Прод (VDS)

```bash
cp .env.example .env    # заполнить BOT_TOKEN и POSTGRES_PASSWORD
docker compose up -d --build
```
Контейнер при старте сам применяет миграции (`alembic upgrade head`) и заливает
вопросы. Приложение слушает `127.0.0.1:8000`. Снаружи его нужно отдавать через
nginx или Caddy с HTTPS: Telegram Mini App работает только по https. Для WebSocket
нужны заголовки `Upgrade`/`Connection`.
